## Целевая модель: проверка по этапам

Каждый этап потребляет **выход предыдущего**, эталон лежит рядом с `.c`:

```
.c  ──▶  preprocess  ──▶  .pp
              │
              ▼
           lexer  ──▶  .l      (токены от текста .pp, не от сырого .c)
              │
              ▼
           parser ──▶  .p / .ast   (AST — отдельная стадия; .p ≡ .ast)
              │
              ▼
           IR     ──▶  .ir        (вход: AST, не сырой parse с .c)
              │
              ▼
         HighIR …   ──▶  .hir / .mir / .lir  (когда появятся)
```

**Смысл:** тест PP не знает про лексер; тест лексера не знает про парсер; каждый слой проверяется изолированно против **независимого** эталона.

---

## Что сейчас в раннерах (расхождение)

| Стадия | Эталон | Раннер сегодня | Проблема |
|--------|--------|----------------|----------|
| PP | `.pp` | `preprocess(.c)` → `.pp` | ✓ согласовано |
| Lex | `.l` | `lexerPure(.c)` | читает **сырой** `.c`, не `.pp` |
| Parse | `.p`/`.ast` | `lexer(.c)` → `parse` | то же |
| IR | `.ir` | `preprocess` → `lex` → `parse` → `toIr` | ✓ ближе к цепочке, но lex/parse всё ещё не через `.pp`-эталон |

Для «чистого» C (без `#define` / `#include`) сырой `.c` ≈ `.pp` — расхождение не видно.  
Для файлов с директивами препроцессора — эталоны `.l`/`.p` **долны** описывать post-PP текст, а раннер пока гоняет pre-PP → тест падает **правильно**, но по причине **раннера**, не обязательно бага стадии.
